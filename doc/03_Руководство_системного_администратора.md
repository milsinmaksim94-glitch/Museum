# Раздел 3. Руководство системного администратора

## 3.1 Системные требования

| Параметр | Значение |
|---|---|
| ОС | Android 7.0 (API 24) и выше |
| Оперативная память | от 2 ГБ |
| Свободное место | от 50 МБ |
| Интернет | нужен для общей базы (без интернета работает локальная копия) |

## 3.2 Установка

**Способ 1. Через APK-файл**
1. Скачать `app-debug.apk` из раздела **Releases** на GitHub.
2. Перенести файл на телефон и открыть его.
3. Разрешить установку из неизвестных источников, если телефон спросит.

**Способ 2. Через Android Studio**
1. Клонировать репозиторий: `git clone <ссылка на репозиторий>`.
2. Открыть папку проекта в Android Studio (File → Open).
3. Дождаться синхронизации Gradle.
4. Подключить телефон или запустить эмулятор и нажать **Run ▶**.

Сборка APK: **Build → Build App Bundle(s) / APK(s) → Build APK(s)**. Готовый файл лежит в `app/build/outputs/apk/debug/app-debug.apk`.

## 3.3 Общая база Firebase

Общие данные хранятся в облачной базе Firebase Firestore (бесплатный тариф Spark). Настройка проекта, один раз:

1. На console.firebase.google.com создать проект.
2. **Add app → Android**, package name `com.museum.app`, скачать `google-services.json` и положить в папку `app/` проекта.
3. **Databases & Storage → Firestore → Create database**. На вкладке **Rules** разрешить чтение и запись (`allow read, write: if true;`) - для учебного проекта.
4. При первом запуске приложение само загрузит стартовые данные в пустую базу.

Посмотреть и изменить данные можно в консоли Firebase: Firestore → коллекции `users`, `places`, `halls`, `exhibits`, `guides`, `tours`, `comments`, `favorites`, `bookings`. Коллекция `meta` хранит отметку о загрузке стартовых данных - если удалить всю базу, удалите и её, тогда стартовые данные загрузятся заново.

## 3.4 Локальная база данных

- СУБД: SQLite (встроена в Android).
- Файл базы: `/data/data/com.museum.app/databases/museum.db`.
- Посмотреть базу можно в Android Studio: **View → Tool Windows → App Inspection → Database Inspector**.
- При первом запуске база создаётся автоматически и заполняется стартовыми данными (3 площадки, 6 залов, 14 экспонатов с фото, 5 экскурсоводов, 7 экскурсий, администратор), затем заменяется данными из Firebase.

## 3.6 Возможности панели администратора

Панель открывается из «Профиль → Панель администратора». В ней пять вкладок:

- **Экспонаты** - список; «+» добавляет экспонат, нажатие на экспонат открывает редактирование (фото из галереи, материал, инвентарный номер), корзина удаляет.
- **Залы** - справочник залов: добавление через «+» (с выбором площадки), удаление корзиной. Вместе с залом удаляются его экспонаты и экскурсии.
- **Гиды** - экскурсоводы: добавление и редактирование с фото из галереи, удаление (вместе с их экскурсиями).
- **Площадки** - здания музея: адрес, метро, часы, телефон, координаты, фото; удаление каскадно удаляет залы площадки.
- **Брони** - все записи всех пользователей; нажатие открывает выбор статуса.

## 3.7 Сброс данных

Очистка данных приложения на телефоне (**Настройки → Приложения → Музей → Хранилище → Очистить данные**) удаляет только локальную копию - при следующем запуске данные снова скачаются из Firebase. Чтобы сбросить общие данные, удалите коллекции в консоли Firebase (включая `meta`).
